# 永久网址政策与 GPT 工作执行指令

- /、/regions/、/search/、/archives/、/about/
- /villages/v000001/
- /persons/p000001/
- /archives/a000001/

上述人物/村庄/谱页ID为格式示例；首批档案预留a000001。不要根据图片文件名推断印刷页码；pg000018仅是稳定页面ID示例，必须根据清单实际分配。人物ID不可由姓名拼音生成，村庄ID不可由行政区划或村名生成。行政区划变化、村名更名、谱页调整、人物更名均不得改变已发布URL。合并/迁移时维护redirects.json并在实际托管层提供301或兼容旧页；不能静默404。发布前固定canonical为https://fengshizupu.com对应路径；.cn不作为重复索引站。

## 工作执行顺序
### P0 仓库审计
读取全部目录、原谱文件、现有配置与Git历史；列出27张图片实际存在情况、尺寸、文件格式、命名、是否有重复、页码是否可辨。保留用户上传的全部原件。若数量或顺序不一致，先报告并使用可验证的部分继续搭框架，禁止凭空补图。

### P1 基础工程
实现可静态导出的Next.js项目、统一导航、页脚、移动端、SEO、GitHub Pages部署工作流和域名CNAME（只有域名指向Pages的配置由用户另行授权）；完成首页、地区、村庄、档案目录。

### P2 原谱模块
从真实图片清单生成第一册档案，支持页码目录、原图缩放、翻页、图片下载、整册PDF；不改变原图。给每张图稳定页ID、原印页码独立字段。

### P3 人物数字化
逐页识别、录入姓名/世代/亲属关系/来源；建立待核实报告和人工校对界面或校对文件。不得把AI猜测标为已核实。跨页世系需要证据确认。资料未全部校对前，可先上线档案浏览及明确标注的试验性搜索。

### P4 搜索和世系
实现中文部分姓名搜索、简繁异体别名、同名分离、来源筛选、人物详情、祖先/后代展开、人物定位原谱。保持无结果和待核实状态清晰。

### P5 质量与发布
运行类型检查、静态构建、数据校验、链接检查、移动端/桌面端检查、下载文件校验；检查GitHub Pages深链接、SEO、sitemap、canonical、访问速度；总结真实部署情况。国内访问不稳定时只提出替代托管方案，不擅自更换。

6. 是否已部署、域名是否已接入（未完成不得声称完成）。

## 不得做
不得删除或覆盖原始图片；不得臆造祖先/世代/村名；不得把原谱图像的推测识别当作事实；不得先做单村专属路径以后重构；不得强制用户注册；不得把公开静态JSON伪装成私有数据；不得未经同意更改DNS或开通付费服务。
