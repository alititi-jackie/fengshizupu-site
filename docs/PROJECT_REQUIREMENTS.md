# 冯氏族谱｜全国平台产品需求与开发任务书

状态：第一期实施基准。主域名 fengshizupu.com，辅助域名 fengshizupu.cn。
项目定位：面向全国冯氏宗亲的数字族谱档案平台。首期仅收录一个村庄、现有27张原始谱页；不得把全站架构写死为单村。

## 1. 工作方式
- 先审计仓库实际文件树、27张图片的数量/格式/顺序/清晰度，再制定具体执行计划；缺图、缺页或顺序不明时报告，不得假称已完整。
- 按阶段实现、运行构建/测试并提交可核查结果；不要仅交付设计稿。
- 原始图片位于 public/archives/a000100/originals/，不可覆盖、压缩替换或批量重命名；派生缩略图另存。
- 人名、世代、父子关系、配偶、分支必须依据原谱逐项记录来源及核实状态；不能凭模糊图像猜测。AI识别是草稿，人工审核才是已核实。
- 当前阶段不需要登录、Supabase或收费服务。GitHub Pages静态部署；仅公开适合公开的历史资料。原图和JSON一旦公开托管，均可直接获取，不得以隐藏按钮声称访问受限。
- 不擅自改DNS、域名注册设置，不擅自启用收费服务。

## 2. 导航与页面
- / 全国首页：品牌、统一姓名搜索、地区入口、首批族谱、资料收录说明。
- /regions/ 地区目录：省/市/县/乡镇筛选；首期只有真实已录入的地区，不制造空地区内容。
- /search/ 搜索：姓名全称、部分字符、简繁/异体别名；按地区、世代、支系、档案筛选；同名分开展示，显示来源与核实状态；无结果与错误状态。
- /villages/{villageId}/ 村庄详情：地理名称、别名、介绍、关联族谱、相关支系。
- /persons/{personId}/ 人物详情：原谱姓名、别名、世代、支系、亲属关系、资料来源、核实状态；祖先与后代分层展开；点击跳转来源谱页并高亮定位。
- /archives/ 族谱目录。
- /archives/{archiveId}/ 档案详情：原谱信息、版本、页码目录、逐页浏览、下载入口。
- /archives/{archiveId}/pages/{pageId}/ 单页原谱：高分辨率缩放、平移、翻页、页码、图片下载、人物定位（坐标核实后启用）。
- /about/ 平台定位、来源说明、纠错联系、隐私和免责声明。
- 支持移动端优先、键盘操作、图片加载失败提示、可分享的页面标题、面包屑。

## 3. 第一阶段必须交付
1. 完整站点导航、首页、地区目录、档案目录和一个村庄页面。
2. 27张原谱的浏览、缩放、上一页/下一页、单页下载、按实际顺序的整册PDF下载；缺页须清晰提示。
3. 结构化人物数据与亲属关系，支持全名/部分姓名搜索、同名区分、人物详情和上下代世系图。
4. 人物与原谱页面双向关联；具备坐标时可定位，未录坐标时至少打开对应页，不虚构位置。
5. 可复现的数据校验、搜索索引生成、构建、链接检查、sitemap生成。
6. GitHub Actions构建并部署GitHub Pages；项目应能本地运行与静态导出。
7. 清楚显示资料来源和核实状态；没有核实的字段显示待核实，不自动补全。
8. README含本地运行、资料录入、部署、域名配置及故障排查。

## 4. 第二阶段（预留，不阻塞首期）
- 字辈表、迁徙历史、同祖关系查询、族谱多版本对照、跨村同一人物人工关联、审核工作流、族人反馈与资料征集。
- 需要服务端身份审核或私密资料时再单独设计数据库和授权系统；不要在静态GitHub Pages上伪造隐私保护。

## 5. UI/SEO
- 网站名称“冯氏族谱”；主站 fengshizupu.com；简体中文为主。
- 设计稳重清晰、适合长辈；手机搜索入口显著，族谱原图可放大且不被裁切。
- 生成唯一canonical、OG元数据、sitemap、robots、语义化标题；不为尚未录入的省份或人物生成空壳SEO页。
- 主域名为.com，.cn计划301重定向至.com；GitHub Pages本身不能保证完成双域名301，需另行配置并验证。
- 中国内地访问GitHub Pages稳定性需实测，不能保证可用；保留未来迁移托管但不改变永久路径的能力。

## 6. 验收条件
- 所有原始图像可访问且文件未改动；原图数量与顺序核实。
- 姓名搜索可返回已录人物，同名不误合并，未录人物不伪造。
- 人物关系无自指、循环、无效ID；每条关系可追溯谱页或标明待核实。
- 27页（如确实完整）可逐页浏览并正确生成下载PDF。
- 电脑与手机主要路径正常，刷新深层URL仍可打开。
- 静态构建、类型检查、数据校验、内部链接检查通过。
- 交付报告明确：已完成、待人工核对、风险、部署状态、下一步。
